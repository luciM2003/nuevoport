In one minute

Problem

Quality data lived in six Excel files and four Power BI dashboards kept up to date by hand. Unhappy customers surfaced in a survey weeks after delivery.

Approach

I kept the spreadsheets the team already used as the source and designed around roles: what each person has to do, see and not see. Urgent cases come before any chart.

Outcome

One portal instead of four dashboards, six files that sync on their own, six roles with their own permissions, and seconds between saving an Excel file and seeing it on screen.

01The challenge

Four dashboards, six spreadsheets and nobody looking at the same thing.

The Quality team follows factory NPS, workshop NPS, call-center surveys, Mystery Shopper visits, deliveries and audits. Each source lived in its own file and somebody had to keep the dashboards alive.

Scattered data

  • Six separate Excel files
  • Four Power BI dashboards
  • Updating depended on one person

Late complaints

  • An unhappy customer showed up in a survey weeks after delivery
  • By then the problem was harder to fix

Constraints

  • How the spreadsheets are filled could not change
  • Busy people, often on their phones
  • Each role must see only what is theirs

How might we get the whole team looking at the same numbers, always up to date, and have an unhappy customer handled before they appear in a survey?

02Research & discovery

Start from the files people already trust.

The audit of the existing sources found two problems: where the data lived, and what people typed into it.

Comments written in numeric columns and salespeople entered as “Others” were skewing results without anyone noticing. A faster dashboard with the same doubts would have solved nothing.

Evidence

What was known

  • Six files feed every metric the team follows
  • Typing errors were changing the results
  • Sharing a dashboard meant sharing it whole, with everyone’s results

Assumptions

What was designed as a hypothesis

  • A salesperson will report a problem if it takes seconds from the phone
  • A number with its sample size is trusted more than a number alone

Still open

What real use has to confirm

  • How long Quality takes to call after a report
  • How many survey answers are recovered by cleaning the sources

Three principles

Nobody enters data twice

The portal adapts to the spreadsheets in use, not the other way round.

Every number in context

Each metric says how many cases it is based on and how it compares with the previous month.

Urgent first

A customer nobody has called yet is seen before any chart.

04Design exploration

Five changes to the team’s daily work.

  1. Before

    Updating was a chore

    Someone exported the spreadsheets and refreshed the dashboards. If they didn’t, the numbers went stale.

    After

    It updates when the Excel is saved

    A background process uploads changes within seconds. Uploading the same file again never duplicates anything.

    What it cost: it depends on a process running on one computer, so there is a manual fallback screen.

  2. Before

    A complaints module

    A complaint was recorded once the customer had already said so in a survey.

    After

    Early detection, from the phone

    Whoever notices an unhappy customer logs it on the spot, and Quality calls.

  3. Before

    Filtering on every dashboard

    Looking at September in sales and then in surveys meant choosing the month again.

    After

    Filters that follow you

    Month and salesperson persist between screens, and several months can be added up.

    What it cost: the PDF report asks for a single month, because with several it isn’t clear what to compare with.

  4. Before

    Everyone saw everything

    Sharing a dashboard meant sharing every salesperson’s results.

    After

    Permissions in the database

    The rules live in the data, not only in which buttons are shown. A new account sees nothing until it is activated.

    What it cost: Quality has to activate each person.

  5. Before

    Messy data, doubtful numbers

    Typing errors distorted results without anyone noticing.

    After

    Don’t guess, explain

    The portal discards what it can’t read and each metric shows how many cases it uses. The guide explains what to fix in the Excel.

05Design system

07Implementation & collaboration

Adoption was part of the design.

I designed the interface and implemented it in React and TypeScript over Supabase, so each decision reached production without a translation step.

Getting in

A QR code opens the portal on the phone and three steps install it.

Joining

Each person creates their account and Quality activates it with a role. No shared passwords.

If something fails

A “what you see, what it means” table and a file that checks whether sync is running.

I wrote the guide in the portal’s own words: how to get in, what each screen shows and what to do when something doesn’t work.

What changed.

Time saved and response times haven’t been measured yet. Both are on the list below.

09Learnings & next steps

Respecting how people already work lowered the barrier.

Learnings

  • Nobody had to learn a new way of entering data
  • A number without context breeds distrust: “out of how many” is part of the design
  • Designing permissions is designing the experience: what someone doesn’t see also counts

Next steps

  • Measure how long Quality takes to call a customer after a report
  • Add alerts when a metric drops below its target
  • Darken the faint captions so they pass AA
  • Clean up the source spreadsheets with the team so that more answers count
